# Phase 5 — UI Design Contract

> Визуальный и интеракционный контракт фронтенд-фазы. Сгенерировано gsd-ui-researcher, проверяется gsd-ui-checker.

**Поверхности фазы (в охвате):**
- **Select зависимости в форме add/edit** (`AddItemForm`) — новое необязательное поле `Зависит от покупки` (ITEM-06, D-01). shadcn `Select` из СВОИХ покупок пользователя, исключая саму себя и cycle-небезопасные кандидаты (D-05). Ставится в блок необязательных полей, после `Срок` и перед `Сомнения`.
- **Индикатор блокировки на карточке** (`ItemCard`) — отдельная строка `Lock` (lucide) + подпись «Заблокировано: {название зависимости}» (DEP-02, D-04). Рендерится ТОЛЬКО когда покупка заблокирована. Производное состояние на чтении (D-02).
- **`disabled`-чекбокс «куплено»** (`PurchaseCheckbox`) — у заблокированной покупки чекбокс недоступен (DEP-01, D-03/D-04); тач-зона-обёртка 44px сохраняется, но не переключает статус.
- **Валидация цикла** (форма/Server Action) — при выборе cycle-небезопасной покупки показывается ошибка поля (D-05); серверный guard `setItemPurchased` отклоняет отметку заблокированной покупки (D-03, defense-in-depth).

Mobile-first (LIST-08, перенос Фазы 4). Весь пользовательский текст — на русском; код/идентификаторы/пути — на английском (перенос из Фаз 1–4).

**Наследование:** этот контракт **расширяет** `02-UI-SPEC.md`, `03-UI-SPEC.md` и `04-UI-SPEC.md` (все approved). Дизайн-система, шкала отступов, типографика, базовая палитра neutral + синий accent, семантическая палитра приоритета (badge), разбивка очков, ряд действий карточки (`Pencil`/`Trash2`), чекбокс «куплено», секция «Куплено» и undo-тост наследуются **без изменений**. Ниже переопределяются только Phase 5-specific роли: Select зависимости в форме, строка-индикатор блокировки на карточке, `disabled`-состояние чекбокса «куплено» при блокировке, копирайт зависимости/блокировки/цикла.

## Color

Светлая тема — baseline (mobile-first, тёмной темы в этой фазе нет). Базовая палитра neutral + синий accent + семантическая палитра приоритета наследуются без изменений.

| Role | Value | Usage (Phase 5) |
|------|-------|-----------------|
| Dominant (60%) | `#FFFFFF` | Фон формы, фон карточки (заблокированная карточка НЕ приглушается — см. ниже) |
| Secondary (30%) | `#F5F5F5` (neutral-100) + бордер `#E5E5E5` (neutral-200) | Приглушённый текст `#737373` (neutral-500 / `text-muted-foreground`): строка «Заблокировано: …», иконка `Lock`; `disabled`-чекбокс приглушается штатным Radix-стилем (opacity + `cursor-not-allowed`) |
| Accent (10%) | `#2563EB` (blue-600) | Без нового применения. Фокус-ринг триггера `Select` зависимости (наследуется как у остальных Select). НЕ применяется к строке блокировки, иконке `Lock`, badge |
| Destructive | `#DC2626` (red-600) | Только текст ошибки валидации цикла (`FormMessage`, наследуемый паттерн ошибок поля). Блокировка НЕ деструктивна и НЕ красная |

Accent reserved for (наследуется): checked-состояние `Checkbox`-контролов, фокус-ринг интерактивных контролов (включая новый `Select` зависимости), фон primary-кнопок. Ничего больше.

**Лечение заблокированной карточки (Phase 5-specific, дискреция зафиксирована):**
- Заблокированная карточка **НЕ приглушается** (`opacity` не трогаем): в отличие от купленной (Фаза 4, `opacity-70` + `line-through`), заблокированная покупка — активная и релевантная, её просто пока нельзя купить. Приглушение конфликтовало бы с семантикой «куплено».
- Статус «заблокировано» кодируется **избыточным каналом, не цветом**: иконка `Lock` + текстовая подпись «Заблокировано: {название}» + `disabled`-чекбокс. Соответствует принципу «не только цветом» (перенос LIST-06). Один лишь `disabled`-чекбокс (визуально приглушённый) НЕ является единственным сигналом — рядом всегда есть иконка и текст с причиной.
- Иконка `Lock` и подпись — `text-muted-foreground` (нейтральные), НЕ `destructive`: блокировка — это ограничение-подсказка, а не ошибка.

## Copywriting Contract

Тон — единый неформально-нейтральный русский (перенос из Фаз 1–4), без восклицаний. Наследуемые тексты (подписи полей формы, тексты валидации, empty-состояния списка, undo-тост, разбивка очков) — из прежних UI-SPEC, не переформулируются. Ниже — только НОВЫЕ строки Фазы 5.

| Element | Copy |
|---------|------|
| Подпись поля зависимости (`FormLabel`) | `Зависит от покупки` |
| Placeholder `Select` (ничего не выбрано) | `Выберите покупку (необязательно)` |
| «none»-опция (сбросить зависимость в null) | `Без зависимости` |
| `Select` при 0 кандидатов (триггер `disabled`) | `Нет других покупок` |
| Индикатор блокировки на карточке | `Заблокировано: {название зависимости}` |
| `aria-label` `disabled`-чекбокса заблокированной покупки | `Нельзя отметить купленной, пока не куплено «{название зависимости}»` |
| Ошибка валидации цикла (`FormMessage`) | `Нельзя выбрать эту покупку — получится цикл зависимостей.` |
| Error-тост серверного guard-отклонения (D-03) | `Сначала купите товар, от которого зависит эта покупка.` |
| Destructive confirmation | **Нет.** Фаза 5 не добавляет деструктивных действий. Выбор/сброс зависимости и блокировка — недеструктивны и обратимы (сменить/убрать зависимость можно в любой момент через edit). Подтверждение НЕ требуется |

**Про «none»-опцию:** shadcn/Radix `SelectItem` не допускает пустое значение — «Без зависимости» реализуется через явный sentinel-value (напр. `"none"`), который слой формы/Zod маппит в `dependsOn: null`. Это деталь реализации; контракт фиксирует лишь видимый текст и то, что опция очищает зависимость.

**Про подстановку `{название зависимости}`:** в подпись блокировки и в `aria-label` подставляется `title` покупки-зависимости, найденной lookup'ом по `dependsOn` в уже загруженном RSC-наборе (D-02, без доп. запроса). Длинное название усекается (см. §UI Considerations, backstop).

## Component Behaviour Contracts

### Поле зависимости в форме add/edit (`AddItemForm`, ITEM-06 / D-01 / D-05)
Раскладка (дискреция зафиксирована): поле встаёт в блок необязательных атрибутов **после `Срок` и перед `Сомнения`** — все не-очковые необязательные поля (`Ссылка`, `Описание`, `Цена`, `Срок`, `Зависит от покупки`) идут подряд, а очковые модификаторы (`Сомнения`, `Покупка в кредит`, `Ежемесячный платёж`) остаются сгруппированы внизу.

```
FormField "dependsOn"  (FormItem, тот же ритм grid gap-4)
  ├─ FormLabel «Зависит от покупки»                          (Label 14/600)
  ├─ Select (trigger: h-11 w-full text-base, аналог category)
  │     ├─ placeholder «Выберите покупку (необязательно)»    (когда null)
  │     ├─ опция «Без зависимости»  (sentinel → null)        (первой в списке)
  │     └─ опции-кандидаты: title других покупок пользователя (Body 16/400)
  └─ FormMessage  (ошибка цикла, destructive — только при попытке цикла)
```

- **Необязательное поле:** `dependsOn` — optional/nullable в `itemInputSchema` (Zod). По умолчанию null (placeholder). Опция «Без зависимости» позволяет явно очистить ранее выбранную зависимость в edit-режиме.
- **Состав кандидатов (D-05):** список = ДРУГИЕ покупки пользователя, минус сама покупка (self), минус cycle-небезопасные (те, что по цепочке `depends_on` уже зависят от текущей). Купленные покупки из НОВОГО выбора исключаются (купленная зависимость никогда не блокирует → выбор бесполезен); в edit-режиме текущая выбранная зависимость остаётся показанной/выбранной, даже если стала купленной (консистентность prefill — деталь плなннинга).
- **Кандидаты приходят пропом** из RSC-обёртки формы (`/list/new`, `/list/[id]/edit`) как массив `{ id, title }` — по образцу того, как edit-страница отдаёт `initialValues`. Никакого клиентского запроса.
- **Валидация цикла (D-05):** проверка выполняется на СЕРВЕРЕ (Server Action / Zod-refine с обходом цепочки `depends_on`). При цикле — ошибка поля через `FormMessage` (`Нельзя выбрать эту покупку — получится цикл зависимостей.`), submit не проходит. Клиентская фильтрация кандидатов уже прячет большинство cycle-небезопасных, серверная проверка — авторитетный backstop (never-trust-client).
- **Визуальный якорь формы** остаётся прежним — primary-кнопка `Добавить покупку` / `Сохранить`; поле зависимости — рядовое необязательное, без выделения.

### Индикатор блокировки на карточке (`ItemCard`, DEP-02 / D-02 / D-04)
Раскладка (дискреция зафиксирована) — новая строка-индикатор МЕЖДУ рядом заголовка и рядом действий, рендерится ТОЛЬКО при `blocked === true`:

```
CardContent (flex-col gap-2)
  ├─ Ряд заголовка (flex items-center gap-2):
  │     ├─ PurchaseCheckbox  (h-11 w-11 тач-зона; disabled при blocked)   [Фаза 4 + P5]
  │     ├─ title  (min-w-0 truncate, Heading 20/600)                       [без изменений]
  │     └─ PriorityBadge  (shrink-0)                                        [без изменений]
  ├─ Строка блокировки (flex items-center gap-1, ТОЛЬКО при blocked):      ← НОВОЕ
  │     ├─ Lock  (size-4 shrink-0, aria-hidden, text-muted-foreground)
  │     └─ span «Заблокировано: {название}»  (Meta 14/400 muted, min-w-0 truncate)
  └─ ScoreBreakdown (триггер разбивки + edit + delete)                     [без изменений]
```

- **Условный рендер:** строка блокировки присутствует в DOM только когда покупка заблокирована. Незаблокированная покупка (нет зависимости ИЛИ зависимость уже куплена) индикатора НЕ показывает — карточка остаётся чистой (дискреция «где показывать название зависимости» зафиксирована: только в строке блокировки).
- **Флаг `blocked` — производный на чтении (D-02):** вычисляется в `list/page.tsx` (RSC) из уже загруженного набора: `blocked = dependsOn != null && lookup(dependsOn)?.purchasedAt == null`. `ItemCard` получает пропы `blocked: boolean` и `dependencyTitle: string | null` (примитивы, граница RSC→client на примитивах — перенос §Pitfall 4 Фазы 4). Никакого доп. запроса, никакого `Date` в клиенте.
- **Название зависимости** усекается при длинном title (`min-w-0 truncate`), строка не ломает карточку (backstop).
- **Заблокированная карточка не приглушается** (§Color) — редактирование/удаление доступны как обычно (ряд действий не затронут); ограничение касается только отметки «куплено».

### `disabled`-чекбокс «куплено» при блокировке (`PurchaseCheckbox`, DEP-01 / D-03 / D-04)
- `PurchaseCheckbox` получает новый проп `blocked: boolean`. При `blocked` вложенный `Checkbox` — `disabled` (штатный Radix-стиль: приглушение + `cursor-not-allowed`), `onCheckedChange` не срабатывает. `aria-label` меняется на `Нельзя отметить купленной, пока не куплено «{название зависимости}»` (передаётся `dependencyTitle` пропом).
- **Обёртка-тач-зона 44px сохраняется** (`h-11 w-11`) для визуальной стабильности ряда заголовка, но в `disabled` тап ничего не делает.
- **Тултип НЕ добавляется** (дискреция зафиксирована, CONTEXT): иконка `Lock` + подпись «Заблокировано: …» + `disabled`-состояние уже объясняют причину избыточно. Меньше зависимостей и визуального шума.
- **Авто-разблокировка (D-02):** когда покупку-зависимость отмечают купленной, `PurchaseCheckbox` зависимости уже вызывает `router.refresh()` (Фаза 4) → RSC пересчитывает `blocked` для зависимой покупки → на следующем рендере её чекбокс становится активным, строка блокировки исчезает. Ничего дополнительно хранить/инвалидировать не нужно.
- **Серверный guard (D-03, defense-in-depth):** `setItemPurchased` на сервере отклоняет отметку «куплено» для заблокированной покупки (`{ ok: false, error }`). В нормальном UI чекбокс `disabled`, но если запрос обойдён — клиент показывает error-тост `Сначала купите товар, от которого зависит эта покупка.` (тот же шов `toast.error`, что STATUS_ERROR в Фазе 4; текст берётся из ответа сервера).
