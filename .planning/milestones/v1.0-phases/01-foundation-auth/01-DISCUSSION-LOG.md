## Поля регистрации

**Какие поля запрашиваем при регистрации?**

| Option | Description | Selected |
|--------|-------------|----------|
| Только email + пароль | Минимум трения, Better Auth из коробки, в шапке показываем email | ✓ |
| email + пароль + имя | Отображаемое имя для приветствия, чуть больше полей | |

**Нужна ли верификация email в v1?**

| Option | Description | Selected |
|--------|-------------|----------|
| Нет, сразу вход | Без SMTP-настройки, быстрее для MVP/семейного приложения | ✓ |
| Да, подтверждение по ссылке | Требует email-провайдера и доп. экранов | |

**Требования к паролю?**

| Option | Description | Selected |
|--------|-------------|----------|
| Минимум 8 символов | Баланс безопасности/удобства, дефолт Better Auth | ✓ |
| Минимум 12 символов | Строже, больше трения | |
| Минимум 6 символов | Мягче | |

**User's choice:** email+пароль; без верификации; пароль от 8 символов.
**Notes:** Семейный/личный сценарий → приоритет удобства.

## Точка входа гостя

**Что видит неавторизованный на корневом URL (/)?**

| Option | Description | Selected |
|--------|-------------|----------|
| Редирект на /login | Приложение = список за авторизацией, лендинг не нужен | ✓ |
| Простой лендинг | Описание + кнопки Вход/Регистрация | |

**После успешной регистрации пользователь...**

| Option | Description | Selected |
|--------|-------------|----------|
| Сразу в список (автовход) | Автоматически создаётся сессия, меньше шагов | ✓ |
| На страницу входа | Нужно войти вручную | |

**Как выглядит пустой список в Фазе 1?**

| Option | Description | Selected |
|--------|-------------|----------|
| Заглушка + подсказка | «Список пуст — скоро можно будет добавить покупки» | ✓ |
| Просто «Список пуст» | Минимальный текст без подсказок | |

**User's choice:** редирект на /login; автовход после регистрации; empty state с подсказкой.
**Notes:** Форма добавления — только в Фазе 2, в Фазе 1 её нет.

## Оболочка и выход

**Какой каркас (layout) закладываем в Фазе 1?**

| Option | Description | Selected |
|--------|-------------|----------|
| Минимальная шапка | Название + email + «Выйти», каркас для будущих экранов | ✓ |
| Без общей шапки | Кнопка выхода на странице списка | |

**Куда попадает пользователь после выхода?**

| Option | Description | Selected |
|--------|-------------|----------|
| На /login | Сразу экран входа, сессия очищена | ✓ |
| На корень / | Корень всё равно редиректит на /login | |

**User's choice:** минимальная шапка; после выхода → /login.

## Поведение сессии

**Нужен ли чекбокс «Запомнить меня»?**

| Option | Description | Selected |
|--------|-------------|----------|
| Нет, всегда длинная сессия | Проще, сохраняется между перезагрузками (AUTH-02) | ✓ |
| Да, чекбокс на входе | Больше контроля, больше вёрстки | |

**Сколько живёт сессия?**

| Option | Description | Selected |
|--------|-------------|----------|
| 30 дней | Удобно, дефолт Better Auth | ✓ |
| 7 дней | Чаще просит войти | |
| 90 дней | Очень редко просит войти | |

**При отсутствии/истечении сессии на защищённой странице...**

| Option | Description | Selected |
|--------|-------------|----------|
| Редирект на /login | Просто и предсказуемо | ✓ |
| Сообщение + ссылка | «Сессия истекла» + ссылка на вход | |

**User's choice:** всегда длинная сессия; 30 дней; при истечении → редирект на /login.

## Deferred Ideas

- Верификация email / восстановление пароля / 2FA / magic links — не v1.
- Рейт-лимит попыток входа — не в Фазе 1.
- Отображаемое имя пользователя и приветствие по имени — потребует миграции (см. D-01).
