## Trust Boundaries

| Boundary | Description |

| client → Server Action `updateItem` | Недоверенный payload формы (значения полей + id покупки) пересекает границу сервера |
| browser → RSC route `/list/[id]/edit` | Параметр маршрута `id` контролируется пользователем — может указывать на чужую покупку |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-01 | Elevation/Tampering (IDOR) | `updateItem` / `updateItemForUser` | high | mitigate | userId только из `requireUser()`; `updateItemForUser` scope-ит запрос `and(eq(items.id,id), eq(items.userId,userId))`; чужая/несуществующая → null (no-op). Якорь: изоляция update в items.iso.test.ts (Task 2). |
| T-3-02 | Information Disclosure (IDOR read) | `findItemForUser` / `edit/page.tsx` | high | mitigate | read scoped по userId; чужая/отсутствующая → `notFound()` (404), форма не предзаполняется чужими данными. Якорь: изоляция read (Task 2) + e2e. |
| T-3-03 | Tampering (mass-assignment) | `updateItem` payload | high | mitigate | userId никогда из payload; `ItemInsertData` исключает id/userId; repo подмешивает userId из сессии в WHERE. |
| T-3-04 | Tampering (never-trust-client) | `updateItem` input | medium | mitigate | `itemInputSchema.safeParse` на сервере до записи; невалидное → `{ ok: false }`, без записи. |
