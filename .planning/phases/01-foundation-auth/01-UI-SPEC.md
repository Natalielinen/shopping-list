# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase surfaces (in scope):** register screen, login screen, protected empty-list screen, minimal app header (app name + user email + logout). Mobile-first. All user-facing copy in Russian; code/identifiers/paths in English.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, inline padding |
| sm | 8px | Label-to-input gap, compact stacks |
| md | 16px | Default gap between form fields, card inner padding on mobile |
| lg | 24px | Card padding (desktop), gap between form groups, header horizontal padding |
| xl | 32px | Auth card vertical rhythm, empty-state vertical padding |
| 2xl | 48px | Top offset of auth card from viewport / major vertical break |
| 3xl | 64px | Page-level max vertical spacing |

Exceptions: interactive controls (Button, Input, logout control) have a minimum touch target of **44px** height on mobile (mobile-first accessibility) even though 44 is not on the 4-scale — this is an intentional a11y exception, not arbitrary spacing.

## Typography

Sizes: 14 / 16 / 20 / 24 (4 declared). Weights: 400 regular, 600 semibold (2 declared).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.3 |
| Display | 24px | 600 | 1.2 |

Role mapping for Phase 1:
- **Display (24/600)** — auth card title (`Вход`, `Регистрация`), empty-state heading.
- **Heading (20/600)** — app name in the header.
- **Body (16/400)** — input text, empty-state body copy, links, user email in header. 16px minimum on inputs prevents iOS mobile zoom-on-focus.
- **Label (14/600)** — form field labels, inline validation/error text.

## Color

Light mode is the Phase 1 baseline (mobile-first, no dark-mode toggle in this phase). Values below are the shadcn neutral base plus one product accent.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, auth screen canvas, input fields |
| Secondary (30%) | `#F5F5F5` (neutral-100) + card border `#E5E5E5` (neutral-200) | Muted surfaces, card border, header bottom border, subtle separators. Text: primary `#171717` (neutral-900), muted `#737373` (neutral-500). |
| Accent (10%) | `#2563EB` (blue-600) | See reserved-for list |
| Destructive | `#DC2626` (red-600) | Error / validation message text and error `Alert` accent only |

Accent reserved for: **primary form submit button background** (`Войти`, `Зарегистрироваться`), **inline text links** (login↔register switch), and the **focus ring** on inputs and buttons. NOT used for the logout control (rendered as outline/ghost, neutral), and NOT applied to all interactive elements.

> Accent choice `#2563EB` is a prescriptive **default** (no brand palette exists yet; CONTEXT grants UI discretion). Reversible — override at scaffold time via the shadcn `--primary` CSS variable if desired.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (login) | `Войти` |
| Primary CTA (register) | `Зарегистрироваться` |
| Secondary link (login→register) | `Нет аккаунта? Зарегистрироваться` |
| Secondary link (register→login) | `Уже есть аккаунт? Войти` |
| Logout control | `Выйти` |
| Empty state heading | `Список пуст` |
| Empty state body | `Скоро здесь можно будет добавлять покупки.` |
| Error — login (invalid credentials) | `Неверный email или пароль` (generic — never reveals whether the account exists; per CONTEXT discretion) |
| Error — register (email taken) | `Этот email уже занят` |
| Error — email format | `Введите корректный email` |
| Error — password too short | `Пароль должен содержать минимум 8 символов` |
| Error — empty required field | `Заполните это поле` |
| Error — network/server failure | `Что-то пошло не так. Попробуйте ещё раз.` |
| Destructive confirmation | None — Phase 1 has no destructive data actions. Logout (`Выйти`) is non-destructive (clears session, redirects to `/login`) and requires **no** confirmation dialog. |

Tone: single consistent register, informal-neutral Russian ("вы"-neutral, no exclamation spam). Field-validation copy is terse and instructive.

## UI Considerations

> Shape-rooted UI *state* coverage from the post-verification UI-consideration probe. Empty/error COPY lives in `## Copywriting Contract` above; this section covers state coverage and references those rows.

Applicable state considerations: **25** across 4 surfaces — **19 covered, 1 backstop, 5 dismissed (N/A in Phase 1), 0 unresolved.**

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | login + register forms | ✅ covered | Unfilled form is the default state: blank email/password inputs with labels; empty submit blocked by validation (`Заполните это поле`) |
| loading | login + register forms | ✅ covered | Primary submit button enters a pending state (disabled + spinner, label unchanged) while the Server Action runs — prevents double-submit |
| error | login + register forms | ✅ covered | Field-level errors below inputs (Label role, destructive color) + form-level `Alert` with documented copy (invalid credentials / email taken / network) |
| partial | login + register forms | ✅ covered | Partially-filled form validated per-field on submit (RHF + zod resolver); submit blocked until all fields valid |
| overflow | login + register forms | ✅ covered | On small viewports / open on-screen keyboard the page scrolls vertically; the auth card stays top-centered and never clips inputs |
| long-text | login + register forms | ✅ covered | A long email in an input scrolls horizontally within the field (native input behavior); no layout break |
| empty | protected list screen | ✅ covered | Renders the documented empty-state heading `Список пуст` + body copy — the only list state in Phase 1 |
| loading | protected list screen | ✅ covered | Route-level `loading.tsx` skeleton shown while the authenticated page loads / on navigation |
| error | protected list screen | ✅ covered | Two paths: no/expired session → server redirect to `/login` (D-07); data-layer failure → route-level `error.tsx` boundary with generic message + retry affordance |
| populated | protected list screen | ✅ covered | No populated list in Phase 1; the app header is the populated element (app name + email + logout) |
| zero-one-many | protected list screen | ✅ covered | Only the zero state exists in Phase 1; singular/plural item copy is out of scope until items exist (Phase 2+) |
| long-text | protected list screen | ✅ covered | Empty-state copy is fixed short Russian strings — no dynamic long text on this screen in Phase 1 |
| partial | protected list screen | ⛔ dismissed | No data rows in Phase 1 → no partial-data state is possible |
| overflow | protected list screen | ⛔ dismissed | Empty screen carries no content volume to overflow in Phase 1 |
| loading | app header | ✅ covered | Header renders server-side from the session (app name + email + logout) — no separate client loading state |
| long-text | app header (user email) | 🧪 backstop | Long email truncates with ellipsis (single line), never wraps the header or pushes out the logout control — verified visually |
| empty | app header | ⛔ dismissed | Header renders only on authenticated screens; app name + email always present → no empty state |
| error | app header | ⛔ dismissed | Email is always available from the session when authenticated → no error render path |
| partial | app header | ⛔ dismissed | Header fields (name, email, logout) always render together → no partial state |
