# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase surfaces (in scope):** register screen, login screen, protected empty-list screen, minimal app header (app name + user email + logout). Mobile-first. All user-facing copy in Russian; code/identifiers/paths in English.

| Property | Value |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, inline padding |
| sm | 8px | Label-to-input gap, compact stacks |
| md | 16px | Default gap between form fields, card inner padding on mobile |
| lg | 24px | Card padding (desktop), gap between form groups, header horizontal padding |
| xl | 32px | Auth card vertical rhythm, empty-state vertical padding |
| 2xl | 48px | Top offset of auth card from viewport / major vertical break |
| 3xl | 64px | Page-level max vertical spacing |

Exceptions: interactive controls (Button, Input, logout control) have a minimum touch target of **44px** height on mobile (mobile-first accessibility) even though 44 is not on the 4-scale — this is an intentional a11y exception, not arbitrary spacing.

## Typography

Sizes: 14 / 16 / 20 / 24 (4 declared). Weights: 400 regular, 600 semibold (2 declared).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.3 |
| Display | 24px | 600 | 1.2 |

Role mapping for Phase 1:
- **Display (24/600)** — auth card title (`Вход`, `Регистрация`), empty-state heading.
- **Heading (20/600)** — app name in the header.
- **Body (16/400)** — input text, empty-state body copy, links, user email in header. 16px minimum on inputs prevents iOS mobile zoom-on-focus.
- **Label (14/600)** — form field labels, inline validation/error text.

## Color

Light mode is the Phase 1 baseline (mobile-first, no dark-mode toggle in this phase). Values below are the shadcn neutral base plus one product accent.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, auth screen canvas, input fields |
| Secondary (30%) | `#F5F5F5` (neutral-100) + card border `#E5E5E5` (neutral-200) | Muted surfaces, card border, header bottom border, subtle separators. Text: primary `#171717` (neutral-900), muted `#737373` (neutral-500). |
| Accent (10%) | `#2563EB` (blue-600) | See reserved-for list |
| Destructive | `#DC2626` (red-600) | Error / validation message text and error `Alert` accent only |

Accent reserved for: **primary form submit button background** (`Войти`, `Зарегистрироваться`), **inline text links** (login↔register switch), and the **focus ring** on inputs and buttons. NOT used for the logout control (rendered as outline/ghost, neutral), and NOT applied to all interactive elements.

> Accent choice `#2563EB` is a prescriptive **default** (no brand palette exists yet; CONTEXT grants UI discretion). Reversible — override at scaffold time via the shadcn `--primary` CSS variable if desired.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (login) | `Войти` |
| Primary CTA (register) | `Зарегистрироваться` |
| Secondary link (login→register) | `Нет аккаунта? Зарегистрироваться` |
| Secondary link (register→login) | `Уже есть аккаунт? Войти` |
| Logout control | `Выйти` |
| Empty state heading | `Список пуст` |
| Empty state body | `Скоро здесь можно будет добавлять покупки.` |
| Error — login (invalid credentials) | `Неверный email или пароль` (generic — never reveals whether the account exists; per CONTEXT discretion) |
| Error — register (email taken) | `Этот email уже занят` |
| Error — email format | `Введите корректный email` |
| Error — password too short | `Пароль должен содержать минимум 8 символов` |
| Error — empty required field | `Заполните это поле` |
| Error — network/server failure | `Что-то пошло не так. Попробуйте ещё раз.` |
| Destructive confirmation | None — Phase 1 has no destructive data actions. Logout (`Выйти`) is non-destructive (clears session, redirects to `/login`) and requires **no** confirmation dialog. |

Tone: single consistent register, informal-neutral Russian ("вы"-neutral, no exclamation spam). Field-validation copy is terse and instructive.

## UI Considerations

> Shape-rooted UI *state* coverage. Empty/error COPY lives in `## Copywriting Contract` above; this section covers state coverage and references those rows.

Applicable state considerations resolved: 5 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | protected list screen | ✅ covered | Empty (only) state renders the documented empty-state heading + body copy; there is no populated list in Phase 1 |
| loading | auth submit button (login/register) | ✅ covered | On submit the primary button enters a pending state — disabled + spinner, label unchanged — so the user cannot double-submit while the Server Action runs |
| error | auth forms (login/register/validation) | ✅ covered | Field-level errors render below inputs (Label role, destructive color); form-level auth failures render in an `Alert` using the documented error copy |
| populated | app header | ✅ covered | Header renders app name + authenticated user email + logout control on every protected screen |
| error | protected screen without/expired session | ✅ covered | No error UI — server-side redirect to `/login` (per D-07), so no unauthenticated render of protected content |
| long-text | user email in header | 🧪 backstop | Long email addresses truncate with ellipsis (single line) and never wrap the header or push out the logout control; verified visually |
