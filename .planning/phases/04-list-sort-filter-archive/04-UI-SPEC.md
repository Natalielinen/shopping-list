# Phase 4 — UI Design Contract

> Визуальный и интеракционный контракт фронтенд-фазы. Сгенерировано gsd-ui-researcher, проверяется gsd-ui-checker.

**Поверхности фазы (в охвате):**
- **Панель управления** (`ListControls`, закреплена над списком) — shadcn `Select` сортировки (D-01) + `Checkbox` фильтра «показывать купленные» (D-06). Эфемерное клиентское состояние (`useState`, D-09), сбрасывается к дефолту при перезагрузке.
- **Чекбокс «куплено» на карточке** (`PurchaseCheckbox`, client-leaf) — ведущий контрол в ряду заголовка `ItemCard`, слева от названия (LIST-04). Мгновенная обратимая отметка через Server Action `setItemPurchased(id, purchased)` (D-04/D-05/D-08), не открывает модалку.
- **Секция «Куплено»** (LIST-05, D-06) — отдельный блок с заголовком ниже активных покупок, появляется ТОЛЬКО при включённом фильтре; купленные карточки визуально приглушены (dimmed + strikethrough).
- **Undo-тост** (`sonner`) — после отметки «куплено» показывается тост с действием «Отменить» (D-04). Недеструктивно и обратимо — в отличие от удаления в Фазе 3.

Mobile-first (LIST-08). Весь пользовательский текст — на русском; код/идентификаторы/пути — на английском (перенос из Фаз 1–3).

**Наследование:** этот контракт **расширяет** `02-UI-SPEC.md` и `03-UI-SPEC.md` (оба approved). Дизайн-система, шкала отступов, типографика, базовая палитра neutral + синий accent, семантическая палитра приоритета (badge), разбивка очков и ряд действий карточки (`Pencil`/`Trash2`) наследуются **без изменений**. Ниже переопределяются только Phase 4-specific роли: панель сортировки/фильтра, чекбокс «куплено», секция «Куплено», приглушённое лечение купленных карточек, undo-тост.

**Про `sonner`:** это официальный shadcn-компонент (не сторонний реестр), обёртка над библиотекой `sonner`. Дефолтная обёртка shadcn импортирует `next-themes` для темы. Тёмной темы в проекте нет → **упростить обёртку до фиксированного `theme="light"`** и НЕ добавлять зависимость `next-themes` (минимизация деп). `<Toaster richColors={false} position="bottom-center" />` — mobile-first, тост не перекрывает панель управления сверху.

**Фильтр «показывать купленные» — `Checkbox`, не `Switch`:** D-06 допускает checkbox/switch. Выбран `Checkbox` — уже в проекте (переиспользование примитива `isCredit`), не требует нового компонента `Switch`, консистентен с чекбоксом «куплено» на карточке.

## Color

Светлая тема — baseline (mobile-first, тёмной темы в этой фазе нет). Базовая палитра neutral + синий accent + семантическая палитра приоритета наследуются из `02-UI-SPEC.md` без изменений.

| Role | Value | Usage (Phase 4) |
|------|-------|-----------------|
| Dominant (60%) | `#FFFFFF` | Фон панели управления, фон карточки, фон тоста |
| Secondary (30%) | `#F5F5F5` (neutral-100) + бордер `#E5E5E5` (neutral-200) | Нижний бордер закреплённой панели (`border-b`); разделитель над секцией «Куплено» (`border-t`); приглушённый текст (`#737373` neutral-500) — заголовок секции, strikethrough-название купленной карточки |
| Accent (10%) | `#2563EB` (blue-600) | **Расширено (control state):** checked-состояние чекбоксов (`Checkbox` фильтра, чекбокс «куплено» на карточке — `bg-primary`, как `isCredit` в форме); фокус-ринг всех интерактивных контролов (Select, чекбоксы). НЕ применяется к badge, тексту, заголовку секции |
| Destructive | `#DC2626` (red-600) | Без нового применения. Отметка «куплено» — **недеструктивна и обратима** (D-04/D-05); красный/`AlertDialog` НЕ используется. Наследуется только delete-иконка из Фазы 3 |

Accent reserved for: **checked-состояние `Checkbox`-контролов** (фильтр + «куплено» + наследуемый `isCredit`), **фокус-ринг** интерактивных контролов, **фон primary-кнопок** (наследуется). Ничего больше.

**Приглушённое лечение купленной карточки (Phase 4-specific, дискреция зафиксирована):**
- Купленная карточка в секции «Куплено» — контейнер `opacity-70`; название — `line-through text-muted-foreground`.
- Strikethrough — **избыточный** канал статуса (не только цвет/прозрачность): «куплено» читается по зачёркнутому названию + checked-чекбоксу + отдельной секции, а не по одному приглушению. Соответствует принципу «не только цветом» (перенос из LIST-06).
- Badge приоритета и разбивка остаются в DOM (приглушены общим `opacity-70`), но приоритет купленной покупки практического веса не несёт — акцент внимания снят намеренно.

## Component Behaviour Contracts

### Панель управления (`ListControls`, D-01/D-06/D-09/D-10)
Раскладка на 375px (дискреция зафиксирована): закреплённая панель над списком, эфемерное клиентское состояние.

```
ListControls  (sticky top-0 z-10, bg-background, border-b, px-4 py-3, flex flex-col gap-3)
  ├─ Ряд A:  Select сортировки  (trigger: w-full h-11, aria-label «Сортировка»)
  │            опции: По приоритету (default) → По дате добавления → По алфавиту   [порядок D-01]
  └─ Ряд B:  label-обёртка (flex items-center gap-2, min-h-11)
               ├─ Checkbox «показывать купленные»  (default OFF, D-06)
               └─ span «Показывать купленные»  (Body 16/400)
```

- **Закрепление:** `sticky top-0` в области прокрутки списка, ниже `AppHeader`. `bg-background` + `border-b` (Secondary) отделяют панель от скроллящихся карточек; без прозрачности — карточки не просвечивают под контролами.
- **Два ряда, не один:** русский label «Показывать купленные» длинный; на 375px размещение Select и чекбокса в одну строку сжало бы обе цели ниже 44px. Вертикальный стек (`flex-col gap-3`) гарантирует полноширинный Select и тач-зону чекбокса.
- **Состояние — клиентское (D-09):** `useState` для `sortKey` (default `priority`) и `showPurchased` (default `false`). НЕ в URL, НЕ в localStorage, НЕ `nuqs`. Перезагрузка сбрасывает к дефолту (приоритет, купленные скрыты).
- **Панель не рендерится при полностью пустом списке** (0 покупок вообще) → показывается наследуемый empty-state `Список пуст`. Нечего сортировать/фильтровать.

### Сортировка (D-01/D-02/D-03)
- Список рендерится RSC (`findItemsForUser` отдаёт ВСЕ покупки, включая купленные, D-10); клиентский компонент держит `sortKey`/`showPurchased` и сортирует/фильтрует на клиенте (набор на пользователя мал).
- Приоритет считается на чтении единым `now` (перенос Фазы 2, SCORE-05); сортировка — в JS, НЕ SQL `ORDER BY` по вычисляемому приоритету (D-03).
- Детерминированные tiebreakers (D-02): приоритет — `total` убыв. → `createdAt` убыв. → `id`; по добавлению — `createdAt` убыв. → `id`; по алфавиту — `title` возр. (`localeCompare('ru')`, case-insensitive) → `createdAt` убыв. → `id`.
- Смена сортировки затрагивает ОБЕ группы (активные и «Куплено»), но секция «Куплено» внутри себя сортируется по `purchasedAt` убыв. (недавно купленные выше — дискреция CONTEXT).

### Чекбокс «куплено» на карточке (`PurchaseCheckbox`, D-04/D-05/D-08)
Раскладка карточки (дискреция зафиксирована) — чекбокс ведущим контролом в ряду заголовка, не конфликтует ни с badge, ни с рядом действий/разбивкой:

```
CardContent (flex-col gap-2)
  ├─ Ряд заголовка (flex items-center gap-2):
  │     ├─ PurchaseCheckbox  (h-11 w-11 тач-зона, shrink-0)   ← НОВОЕ, слева
  │     ├─ title  (min-w-0 truncate, Heading 20/600)          [усечение сохранено]
  │     └─ PriorityBadge  (shrink-0)                          [без изменений]
  └─ ScoreBreakdown (триггер разбивки + edit + delete)        [без изменений, Фаза 3]
```

- Чекбокс — **отдельный client-leaf** по каркасу `DeleteItemButton` (`useState`/`useOptimistic` + async try/catch), но БЕЗ модалки. Живёт в ряду заголовка → **не пересекается** с `Collapsible` разбивки (другой ряд) и рядом иконок действий: тап по «куплено» НЕ переключает разбивку (решение коллизии LIST-07, как в Фазе 3).
- Ведущее положение (слева, «чек-лист»-модель) отделяет тап-зону от badge (справа) и от иконок edit/delete (ряд ниже) → три независимых тач-цели ≥44px.
- **Мгновенно + оптимистично (D-04):** `useOptimistic` флипает состояние сразу; вызывается `setItemPurchased(id, next)` (`requireUser` + scoping по `userId`, D-08 — тот же шов, что `updateItemForUser`/`deleteItemForUser`). Pending-guard от двойного тапа.
- **Успех:** покупка меняет группу — при фильтре ВЫКЛ уходит из активного списка (скрывается); при фильтре ВКЛ переезжает в секцию «Куплено». `router.refresh()` синхронизирует RSC-данные.
- **Undo-тост:** сразу после отметки — `sonner` тост `Покупка отмечена купленной` + `Отменить` (откат через `setItemPurchased(id, false)`).
- **Обратимость (D-05):** снятие checked-чекбокса в секции «Куплено» возвращает покупку в активные (`setItemPurchased(id, false)`), опц. тост `Покупка возвращена в активные`.
- **Сбой:** оптимистичное состояние откатывается; error-тост `Не удалось обновить статус. Попробуйте ещё раз.`; покупка остаётся в исходной группе.

### Секция «Куплено» (LIST-05, D-06)
- Рендерится ТОЛЬКО при `showPurchased === true` И наличии ≥1 купленной покупки. Иначе секции нет (никакого пустого заголовка).
- Раскладка: разделитель `border-t` + отступ `mt-8` (xl) отделяют секцию от активного списка → заголовок `Куплено` (Heading, приглушён) → стопка купленных карточек (те же `ItemCard`, приглушённое лечение из §Color), отсортированных `purchasedAt` убыв.
- Отдельная секция, НЕ вперемешку с активными (D-06). При фильтре ВЫКЛ купленные полностью скрыты.

### Empty-состояния активного списка (новые)
- **Покупок нет вовсе** (0 строк из RSC): наследуемый empty-state `Список пуст` (Фаза 2), панель не рендерится.
- **Есть покупки, но все куплены + фильтр ВЫКЛ:** панель показана; на месте активного списка — heading `Активных покупок нет` + body с подсказкой включить фильтр.
- **Все куплены + фильтр ВКЛ:** на месте активного списка — короткий body `Активных покупок нет.`; секция «Куплено» показана ниже.
