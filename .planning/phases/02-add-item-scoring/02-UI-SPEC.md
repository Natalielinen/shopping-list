# Phase 2 — UI Design Contract

> Визуальный и интеракционный контракт фронтенд-фазы. Сгенерировано gsd-ui-researcher, проверяется gsd-ui-checker.

**Поверхности фазы (в охвате):** страница формы добавления покупки (`/list/new`, полноэкранная, D-06), кнопка входа «Добавить» в `AppHeader` (D-08) и в пустом состоянии списка, карточка покупки с badge приоритета (LIST-06), раскрываемая по тапу разбивка очков (LIST-07), список покупок, отсортированный по убыванию `total` (D-12). Mobile-first. Весь пользовательский текст — на русском; код/идентификаторы/пути — на английском (перенос из Фазы 1).

**Наследование:** этот контракт расширяет `01-UI-SPEC.md` (approved). Шкала отступов, типографика и базовая палитра neutral + синий accent наследуются без изменений — ниже переопределяются только Phase 2-specific роли и добавляется семантическая палитра приоритета.

## Spacing Scale

Наследуется из `01-UI-SPEC.md` без изменений (кратно 4).

| Token | Value | Usage (Phase 2) |
|-------|-------|-----------------|
| xs | 4px | Зазор иконка↔текст в badge и кнопке «Добавить»; знак ± в строке разбивки |
| sm | 8px | Label↔control зазор; внутренние стеки badge; строки разбивки очков |
| md | 16px | Зазор между полями формы по умолчанию; внутренний padding карточки на мобильном; зазор между карточками списка |
| lg | 24px | Padding формы/списка по горизонтали; padding карточки на desktop; группы полей |
| xl | 32px | Вертикальный ритм формы; вертикальный padding пустого состояния |
| 2xl | 48px | Крупный вертикальный разрыв секций |
| 3xl | 64px | Page-level максимум вертикального интервала |

Exceptions: интерактивные контролы (`Button`, `Input`, `Select` trigger, `Checkbox`, тап-зона раскрытия badge/карточки) — минимальная тач-цель **44px** по высоте на мобильном (a11y-исключение, не произвольный интервал). Аффорданс раскрытия разбивки (LIST-07) обязан иметь тач-зону ≥44px.

## Typography

Sizes: 14 / 16 / 20 / 24 (наследуется). Weights: 400 regular, 600 semibold.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.3 |
| Display | 24px | 600 | 1.2 |

Role mapping для Фазы 2:
- **Display (24/600)** — заголовок страницы формы (`Новая покупка`), заголовок пустого состояния (`Список пуст`).
- **Heading (20/600)** — название покупки (`title`) в карточке списка.
- **Body (16/400)** — текст в `Input`/`Textarea`/`Select` (16px минимум — предотвращает zoom-on-focus на iOS), описание, ссылка, тело пустого состояния, число `total` в badge.
- **Label (14/600)** — подписи полей формы, текст ошибок валидации, метка уровня в badge (`Высокий`/`Средний`/`Низкий`), подписи полей в разбивке очков.

## Color

Светлая тема — baseline (mobile-first, тумблера тёмной темы в этой фазе нет). Базовая палитра neutral + синий accent наследуется из `01-UI-SPEC.md`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Фон страницы, канва формы, поля ввода, фон карточки |
| Secondary (30%) | `#F5F5F5` (neutral-100) + бордер `#E5E5E5` (neutral-200) | Приглушённые поверхности, бордер карточки, нижний бордер шапки, разделители. Текст: основной `#171717` (neutral-900), приглушённый `#737373` (neutral-500) |
| Accent (10%) | `#2563EB` (blue-600) | См. список reserved-for |
| Destructive | `#DC2626` (red-600) | Текст ошибок валидации и акцент `Alert` только |

Accent reserved for: **фон primary-кнопки** (`Добавить покупку` на форме, `Добавить` в шапке/пустом состоянии), **фокус-ринг** на полях и кнопках. НЕ применяется к badge приоритета, кнопке «Отмена» (outline/ghost, neutral) и не ко всем интерактивным элементам подряд.

### Семантическая палитра приоритета (badge — D-10)

Функциональные status-цвета для кодирования уровня приоритета. Как и `destructive`, это семантические цвета данных, а не декоративный accent — они **зарезервированы исключительно** за badge приоритета и не участвуют в бюджете 10% accent. Цвет здесь — **избыточный** канал: уровень всегда продублирован числом, текстовой меткой и иконкой (требование LIST-06 «не только цветом»).

| Уровень | Текст/иконка | Фон-подложка | lucide-иконка | Метка |
|---------|--------------|--------------|---------------|-------|
| Высокий | `#B91C1C` (red-700) | `#FEE2E2` (red-100) | `ArrowUp` | `Высокий` |
| Средний | `#B45309` (amber-700) | `#FEF3C7` (amber-100) | `ArrowRight` | `Средний` |
| Низкий | `#525252` (neutral-600) | `#F5F5F5` (neutral-100) | `ArrowDown` | `Низкий` |

Контраст текст/подложка каждой пары ≥ 4.5:1 (WCAG AA). Красный уровня «Высокий» disambiguated от `destructive` контекстом (badge, не кнопка) и тремя избыточными каналами.

> Палитра и пороги — прескриптивный **default** (бренд-палитры нет; D-10 делегирует решение UI-фазе). Reversible: подложки/оттенки настраиваются без изменения контракта уровней.

### Пороги уровней (D-10)

Обоснованы фактическими шкалами (`SUMMARY.md` + D-01…D-05). Практический диапазон `total`: от ~−20 (ненужная хотелка + кредит + сомнения) до ~54 без просрочки и до ~126 при просроченном дедлайне (+100).

| Уровень | Условие | Обоснование |
|---------|---------|-------------|
| Высокий | `total ≥ 30` | Близкий/просроченный дедлайн (+28…+100) либо здоровье/жизненно-важная срочность |
| Средний | `10 ≤ total < 30` | Обычная нужная покупка без давящего срока |
| Низкий | `total < 10` | Низкая ценность/хотелки, штрафы за сомнения и кредит |

Пороги настраиваемы (reversible) — вынести в именованные константы (`PRIORITY_THRESHOLDS`) рядом с движком подсчёта.

## Component Behaviour Contracts

### Форма добавления (`/list/new`, D-06/D-07)
- Полноэкранная одноколоночная раскладка, mobile-first; все поля показаны сразу (D-07), без сворачивания необязательных.
- Порядок: `title` → обязательные Select-ы (`category`, `urgency`, `need`, `benefit`) → необязательные (`link`, `description`, `price`, `deadline`, `doubts`) → `isCredit` → условный `monthlyPayment`.
- `monthlyPayment` появляется/скрывается по `isCredit` без layout-скачка (резервировать место или плавная вставка).
- Внизу: primary `Добавить покупку` (accent) + `Отмена` (ghost/outline neutral). При submit — pending-состояние (disabled + спиннер), защита от двойной отправки.
- Успех → редирект на `/list` (D-09), где новая покупка сразу видна с badge.
- Визуальный якорь страницы — кнопка `Добавить покупку`; вторичный — заголовок `Новая покупка`.

### Badge приоритета (LIST-06, D-10)
- Пилюля на карточке, содержит одновременно: число `total`, текстовую метку уровня (`Высокий`/`Средний`/`Низкий`), lucide-иконку направления и цвет подложки — четыре избыточных канала (не только цвет).
- Компактный формат на мобильном, например: `↑ Высокий · 47`. Метка уровня видима постоянно (не прячется под тап).

### Разбивка очков (LIST-07, D-11)
- Свёрнута по умолчанию; раскрывается по тапу на карточке/аффордансе (`Collapsible`), тач-зона ≥44px.
- Раскрытая панель — список строк «поле → знаковые очки», по одной на вклад:
  `Категория: Здоровье +10`, `Срочность: Жизненно важно +12`, `Необходимость: и нужно и хочется +2`, `Выгода: Приносит доход +2`, `Срок: +28` (или `—` без дедлайна), `Сомнения: −1` (или `нет`), `Кредит: −2` (строка только при `isCredit`), затем `Итого: {total}`.
- Знак ± — основной канал направления; цвет вторичен (не перегружать). Строки — роль Label (14/600) для подписи, Body для значения.

### Список покупок (D-12)
- Рендерится RSC уже отсортированным по убыванию `total` (расчёт на чтении, SCORE-05). Стабильный tiebreaker в Фазе 2 — по `createdAt` (детерминированный формализуется в Фазе 4).
- Каждая карточка: `title` (Heading 20/600) + badge приоритета + аффорданс разбивки. Необязательные поля (цена, ссылка, срок) — по усмотрению планировщика в компактном виде.

## UI Considerations

> Shape-rooted покрытие UI-*состояний*. Copy пустого/ошибочного состояний — в `## Copywriting Contract` выше; здесь — покрытие состояний со ссылкой на те строки.

Применимые состояния: **covered — большинство; 2 backstop; 0 unresolved.**

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | форма добавления | ✅ covered | Незаполненная форма — состояние по умолчанию: пустой `title`, Select-ы в placeholder, `doubts` = `Уверен(а)`; submit блокируется валидацией (`Заполните это поле` / `Выберите значение`) |
| loading | форма добавления | ✅ covered | Submit → pending (disabled + спиннер, лейбл без изменений); защита от двойной отправки |
| error | форма добавления | ✅ covered | Field-level ошибки под контролами (Label role, destructive) + форм-левел `Alert` при сбое сохранения (задокументированный copy) |
| partial | форма добавления | ✅ covered | Частично заполненная форма валидируется per-field (RHF + zod resolver); submit блокируется до валидности всех обязательных |
| conditional | `monthlyPayment` при `isCredit` | ✅ covered | Поле появляется/скрывается по `isCredit` (ITEM-04) без layout-скачка |
| overflow | форма на малом вьюпорте | ✅ covered | Страница скроллится вертикально при открытой экранной клавиатуре; поля не клипаются |
| empty | список покупок | ✅ covered | Пустое состояние: heading `Список пуст` + body + кнопка `Добавить покупку` |
| loading | список покупок | ✅ covered | Route-level `loading.tsx` skeleton при загрузке/навигации |
| error | список покупок | ✅ covered | Нет/истёкшая сессия → redirect `/login`; сбой слоя данных → `error.tsx` с общим сообщением и retry |
| populated | список покупок | ✅ covered | Карточки с badge, отсортированы по убыванию `total` (D-12) |
| zero-one-many | список покупок | ✅ covered | 0 → empty state; 1 и много → одинаковый рендер карточек, сортировка стабильна |
| long-text | `title` в карточке | 🧪 backstop | Длинное название переносится/обрезается без слома карточки и вытеснения badge — проверяется визуально |
| overflow | разбивка очков (все поля заполнены + кредит) | 🧪 backstop | Полная разбивка (7 строк + итог) раскрывается без клиппинга на узком мобильном — проверяется визуально |
| empty | badge приоритета | ✅ covered | `total` всегда вычислим (обязательные поля гарантируют число) → badge всегда рендерится; нет пустого состояния |
