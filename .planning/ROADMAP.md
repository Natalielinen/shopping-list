# Roadmap: Shopping List с приоритетами

## Overview

Путь от пустого репозитория до работающего мультипользовательского списка покупок с автоматическим приоритетом. Сначала закладываем каркас и аутентификацию с изоляцией данных по пользователю (без неё нельзя делать пользовательский CRUD). Затем — центральная ценность продукта: пользователь добавляет покупку и сразу видит автоматически рассчитанный приоритет с разбивкой по полям; чистый модуль подсчёта очков (с внедряемыми «часами», total считается на чтении) встраивается именно в этот вертикальный срез, где приоритет впервые становится виден. Дальше даём управление покупками (редактирование/удаление), затем полноценный список (сортировки, фильтры, архив, mobile-first), и в самом конце — зависимости и блокировку, которые ссылаются на уже существующие покупки.

## Phase Details

### Phase 1: Фундамент и аутентификация

**Goal**: Пользователь может зарегистрироваться, войти, выйти и попасть в свой личный список; заложен каркас приложения и граница изоляции данных по пользователю в слое данных.
**Mode:** mvp
**Depends on**: Nothing (first phase)
**Requirements**: AUTH-01, AUTH-02, AUTH-03, AUTH-04
**Success Criteria** (what must be TRUE):

  1. Новый посетитель может зарегистрироваться по email и паролю и попадает на страницу своего (пустого) списка.
  2. Вернувшийся пользователь может войти, и сессия сохраняется между перезагрузками страницы.
  3. Авторизованный пользователь может выйти из аккаунта с любой страницы и возвращается в состояние «не авторизован».
  4. Любой доступ к данным проходит через слой, ограниченный текущим пользователем, поэтому один пользователь не может загрузить данные другого (подтверждается тестом изоляции на двух пользователях).

### Phase 2: Добавление покупок с автоматическим приоритетом

**Goal**: Авторизованный пользователь может добавить покупку через форму и сразу видит её автоматически рассчитанный приоритет с разбивкой по полям, объясняющей оценку.
**Mode:** mvp
**Depends on**: Phase 1
**Requirements**: ITEM-01, ITEM-02, ITEM-03, ITEM-04, ITEM-05, SCORE-01, SCORE-02, SCORE-03, SCORE-04, SCORE-05, SCORE-06, LIST-06, LIST-07
**Success Criteria** (what must be TRUE):

  1. Пользователь может добавить покупку с обязательным title и обязательными выпадающими списками category / urgency / need / benefit.
  2. Пользователь может заполнить необязательные link, description, price, deadline; переключатель «в кредит» показывает поле monthlyPayment; doubts по умолчанию — «нет сомнений».
  3. У каждой сохранённой покупки виден доступный badge приоритета, чей total равен сумме всех очковых полей, и разбивка того, сколько очков дало каждое поле.
  4. Дедлайн даёт clamp(28 − дней_до_дедлайна, −100, 100) очков (0 без дедлайна), и total покупки отражает сегодняшнюю дату при каждом просмотре (не «замораживается» при создании).
  5. Кредит вычитает 2 очка, а doubts — 0 / −1 / −3, по фиксированным шкалам category/urgency/need/benefit из SUMMARY.

### Phase 3: Редактирование и удаление покупок

**Goal**: Пользователь может изменять и удалять свои покупки, и приоритет пересчитывается после каждого редактирования.
**Mode:** mvp
**Depends on**: Phase 2
**Requirements**: ITEM-07, ITEM-08
**Success Criteria** (what must be TRUE):

  1. Пользователь может открыть существующую покупку, изменить любое поле, сохранить и увидеть приоритет, пересчитанный под новые значения.
  2. Пользователь может удалить свою покупку, и она исчезает из списка.
  3. Редактирование и удаление затрагивают только покупки самого пользователя.

### Phase 4: Список — сортировка, фильтры и архив

**Goal**: Пользователь видит свои покупки как mobile-first список, по умолчанию отсортированный по приоритету, может менять сортировку и фильтры и отмечать покупки купленными с уходом в архив.
**Mode:** mvp
**Depends on**: Phase 3
**Requirements**: LIST-01, LIST-02, LIST-03, LIST-04, LIST-05, LIST-08
**Success Criteria** (what must be TRUE):

  1. Список по умолчанию отсортирован по убыванию приоритета с детерминированным tiebreaker, чтобы покупки с равным приоритетом сохраняли стабильный порядок.
  2. Пользователь может переключить сортировку на «по порядку добавления» и «по алфавиту».
  3. Пользователь может отметить покупку купленной; она уходит в архив и исчезает из списка по умолчанию.
  4. Фильтр «показывать купленные» возвращает архивные покупки в видимый список.
  5. Список и элементы управления удобны на телефоне (mobile-first, достаточные зоны нажатия).

### Phase 5: Зависимости и блокировка

**Goal**: Пользователь может сделать одну покупку зависящей от другой; покупка остаётся заблокированной (нельзя отметить купленной), пока не куплена её зависимость, а заблокированные покупки визуально отличаются.
**Mode:** mvp
**Depends on**: Phase 4
**Requirements**: ITEM-06, DEP-01, DEP-02
**Success Criteria** (what must be TRUE):

  1. При добавлении или редактировании покупки пользователь может выбрать другую свою покупку как зависимость.
  2. Покупку с невыполненной зависимостью нельзя отметить купленной, пока не куплен товар, от которого она зависит.
  3. Заблокированные покупки визуально отличаются в списке, чтобы пользователь понимал, почему с ними пока нельзя действовать.
